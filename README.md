# 🔧 X-UI Socket Fix

Автоматическое исправление проблемы с мёртвыми Unix Domain Socket файлами (`/dev/shm/uds*.sock`) для панели 3X-UI.

## 🐛 Проблема

При некорректном завершении работы Xray-core или внутреннем перезапуске x-ui могут оставаться мёртвые файлы сокетов в `/dev/shm/`. Это приводит к ошибке:

ERROR - XRAY: Failed to start: ... failed to listen Unix Domain Socket on /dev/shm/uds2023.sock ... bind: address already in use

В результате Xray не может запуститься, и VPN перестаёт работать.

## ✅ Решение

Скрипт автоматически выполняет две вещи:

1. **Создаёт systemd override** для службы `x-ui`, который удаляет все `uds*.sock` файлы перед запуском и после остановки службы
2. **Добавляет cron-задачу**, которая каждые 5 минут проверяет и удаляет мёртвые сокеты

## 🚀 Установка одной командой

```bash
bash <(wget -qO- https://raw.githubusercontent.com/Michael-K-cloud/x-ui-socket-fix/main/install-socket-fix.sh)
```

📋 Что делает скрипт

Шаг 1. Проверка прав root
Скрипт не запустится без прав root.

Шаг 2. Проверка наличия x-ui
Скрипт проверяет, установлена ли панель 3X-UI.

Шаг 3. Создание systemd override
Создаёт файл /etc/systemd/system/x-ui.service.d/override.conf:

Шаг 4. Добавление cron-задачи

Добавляет в crontab задачу, которая каждые 5 минут:
Находит все файлы uds*.sock в /dev/shm
Проверяет, используется ли сокет каким-либо процессом
Если сокет мёртвый — удаляет его
Шаг 5. Перезапуск x-ui
Перезапускает службу для применения изменений.
Шаг 6. Финальная проверка
Скрипт автоматически покажет:
Содержимое override.conf
Cron-задачу
Статус x-ui
Процесс Xray (PID и время запуска)
Сокеты в /dev/shm
Ошибки за последний час
🔍 Проверка установки
После установки проверьте:

# Проверить systemd override
```
cat /etc/systemd/system/x-ui.service.d/override.conf
```
# Проверить cron-задачу
```
crontab -l
```
# Проверить статус x-ui
```
systemctl status x-ui
```

⚙️ Требования
Ubuntu 22.04 / 24.04
Установленная панель 3X-UI (x-ui.service)
Права root
🛡️ Безопасность
Скрипт проверяет наличие службы x-ui перед установкой
Не дублирует cron-задачу, если она уже существует
Все изменения сохраняются навсегда и переживают перезагрузку сервера
Нагрузка на сервер минимальна (tmpfs в RAM, операции занимают миллисекунды)
